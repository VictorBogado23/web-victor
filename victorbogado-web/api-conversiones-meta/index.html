API de Conversiones de Meta

API de Conversiones de Meta con GTM server-side

Envío tus eventos a Meta desde el servidor además del píxel, con deduplicación y los datos que Meta necesita para atribuir. Meta recibe más conversiones y optimiza mejor tus anuncios.

Solicitar diagnóstico

Qué incluye

  • Eventos estándar: PageView, ViewContent, AddToCart, Purchase y Lead
  • Deduplicación píxel + API con event_id
  • Email, teléfono, nombre, fbp y fbc
  • Revisión de la calidad de coincidencia
  • Respeto del consentimiento del usuario

Qué es la API de Conversiones de Meta

Es la forma de enviar eventos a Meta desde un servidor en lugar de hacerlo sólo con el píxel en el navegador. Meta recomienda usar las dos: el píxel captura lo que puede en el navegador y la API envía los mismos eventos desde el servidor, para que no se pierdan los que el navegador bloquea.

Por qué el píxel solo no alcanza

Los bloqueadores de anuncios cortan el píxel, iOS limita el seguimiento y Safari borra cookies a los pocos días. Cada evento que no llega es una venta o un lead que Meta no puede usar para optimizar ni para atribuir a tus anuncios.

Cómo la implemento con GTM server-side

  1. Datos en la capa de datos. Cada evento lleva los datos que Meta usa para reconocer a la persona: email, teléfono en formato internacional, nombre y país. Es lo mismo que hace el formulario de este sitio.
  2. Envío al servidor. El contenedor web manda el evento a tu servidor de GTM.
  3. Etiqueta de Meta en el servidor. Configuro la etiqueta de la API de Conversiones con tu token de acceso y el ID del píxel.
  4. Deduplicación. Píxel y API comparten el mismo ID de evento para que Meta cuente cada conversión una sola vez.
  5. Validación. Pruebo con la herramienta de eventos de prueba y reviso la calidad de coincidencia en el Administrador de eventos.

Deduplicación y calidad de coincidencia

Si el píxel y la API mandan el mismo evento sin un ID común, Meta lo cuenta dos veces y tus resultados se inflan. Por eso cada evento lleva un event_id compartido.

La calidad de coincidencia indica qué tan bien Meta puede relacionar un evento con una persona. Mejora cuando el evento incluye email, teléfono, nombre y los identificadores de Meta (fbp y fbc). Los datos personales se envían cifrados con SHA-256, como exige Meta.

Para ecommerce y para generación de leads

En ecommerce envío los eventos de catálogo y compra con valor y productos. En generación de leads envío el evento del formulario y, si tu CRM lo permite, el avance del lead hasta la venta, para que Meta optimice hacia los contactos que de verdad compran.

Preguntas frecuentes

Preguntas frecuentes

¿La API de Conversiones reemplaza al píxel de Meta?

No. Meta recomienda usar ambos con deduplicación. El píxel sigue capturando lo que puede en el navegador y la API completa lo que falta.

¿Qué datos se envían a Meta?

Los datos del evento (tipo, valor, productos) y los datos de coincidencia que tengas permiso de usar: email, teléfono, nombre y país, cifrados con SHA-256.

¿Sirve si genero leads y no vendo online?

Sí. Para leads es donde más se nota, porque cada formulario perdido es un contacto que Meta no puede usar para encontrar personas parecidas.

¿Cuánto mejoran los resultados?

Depende de cuántos eventos se pierden hoy en tu sitio. Antes de empezar medimos la situación actual para poder comparar con números reales.
